I'm happy to announce the release of **Newspipe 12.3.0**. This is a polishing
release: a handier feeds list, notes where you'd expect them, a refreshed
bookmarks page, and a batch of fixes for real-world deployments.

**A feeds list you can sort and filter** — sort by status, title, site,
category, number of articles or creation date, and filter by title or site link
as you type. A new "Created" column also shows when each feed was added.

**Notes everywhere** — the personal notes introduced in 12.1.0 now also
appear on the article details page, with the same add/delete form as the
reading pane.

![The Newspipe home page with the reading pane, the notes panel and the "read later" menu](/images/blog/2026/10/newspipe-12-3-0_home-page.png)

## New Features

- **Sortable and filterable feeds list:** The feeds page gains sortable column
  headers, a filter field and a "Created" column.

## Improvements

- **Notes on the article page:** Article notes are now displayed on the article
  details page too.
- **A modernized bookmarks page:** It now matches the rest of the application —
  underlined tabs, an "Add a bookmark" action, delete confirmation, and visible
  public/private and unread state. The active search or tag is kept when
  switching tabs, and the empty state is finally displayed.
- **More forgiving bookmarks:** Titles and descriptions may now be empty (capped
  at 500 characters), so bookmarklet and Pinboard imports are no longer
  rejected.
- **Translations:** The French and German translations have been updated.
- **Dependencies:** Python and JavaScript dependencies have been updated.

## Fixes

- **psycopg 3:** Newspipe now uses psycopg 3 for PostgreSQL, since SQLAlchemy
  2.1 resolves `postgresql://` URLs to that driver. Editing and deleting feeds
  on PostgreSQL works again, and "No Category" is now stored as `NULL`.
- **Reverse proxies:** JavaScript API requests (such as "mark as read") now
  honour the `PREFIX` setting.
- **LDAP:** `dnspython` is now a declared dependency, so SRV lookups work in the
  Poetry virtualenv, and DNS errors fall back gracefully instead of failing the
  login.
- **CLI:** Id options of `find_vulnerabilities`, `delete_user` and
  `fetch_asyncio` are now parsed as integers.
- **Validation errors:** These now return a readable 400 error instead of a
  500.
